# 配置中心

配置中心用于修改连接、请求监控和 CPA 系统设置。添加模型服务请去 [AI 提供商](./ai-providers.md)，添加账号请去 [OAuth 登录](./oauth.md)或[凭证管理](./accounts.md)。

| 你想做什么                   | 使用哪个区域                    |
| ---------------------------- | ------------------------------- |
| 修改常见 CPA 设置            | 可视化配置                      |
| 查看或编辑完整 `config.yaml` | 源文件配置                      |
| 连接 CPA、开启请求监控       | Manager Server 配置（完整模式） |

## 页面入口

配置中心通常包含三类编辑方式：

- **可视化配置**：适合日常调整。字段分组展示，保存前可以检查变更。
- **源文件配置**：适合熟悉 `config.yaml` 的用户。改动更直接，但也更容易写错格式。
- **Manager Server 配置**：只在 Manager Server 托管面板时可用，用于绑定 CPA、启停采集器和保存 CPAMP 自己的运行设置。

如果某个 Tab 不可用，先确认当前使用的是 CPAMP 轻量面板还是完整模式。轻量面板下不会出现 Manager Server 专属能力；完整模式可以通过 Docker 或原生包安装。在线演示只显示虚构数据，不能用于配置真实 CPA 或验证真实运行状态。

## Manager Server 配置

大多数用户只需要确认三个字段：

- **CPA 地址**：Manager Server 访问 CPA 的地址。容器部署时通常是 Docker 网络里的服务名，不一定是浏览器访问地址。
- **CPA Management Key**：只用于 CPAMP 调用 CPA 管理接口，不是客户端请求模型时使用的 API Key。
- **请求监控**：开启后会启用 CPA 用量统计，并启动 CPAMP 采集器。

保存后回到仪表盘确认 CPA 已连接，再发送一条真实请求检查请求监控。

::: details 高级采集设置

- **采集模式**：自动、RESP 或 HTTP。RESP 需要直连 CPA API 端口，不能走普通 HTTP 反向代理。
- **轮询间隔、批量大小、查询上限**：影响采集延迟和单次读取量。不要把轮询间隔设置得比 CPA 队列保留时间还长。
- **配置来源**：环境变量、SQLite 或未保存。环境变量优先级最高，面板保存不能覆盖环境变量。

没有明确网络限制时保持自动模式和默认数值。只有监控为空或特殊代理环境才需要修改这些字段。

:::

## 可视化配置与源文件配置

日常建议优先用可视化配置，因为它会按功能分组并减少 YAML 格式错误。源文件配置适合这些场景：

- 需要一次性调整多段配置。
- 需要复制已有 `config.yaml`。
- 需要检查可视化配置没有覆盖的字段。
- 需要和部署环境中的配置做差异比对。

保存源文件前，先确认缩进、数组和字符串引号正确。保存后如果页面没有刷新，检查 CPA 是否支持热重载，或是否需要重启运行时。

## 网关配置页的保存语义

网关配置页只编辑 CPA 自己的 `config.yaml`，写法固定为“按分组保存”：

- 每个分组一次保存：只把你改过的字段放进同一个 PATCH，未改动的字段不会被重写。
- “使用默认值”不是写入某个默认数字，而是删除该键，由 CPA 自己决定默认行为。
- 载荷规则族（缺失时填充、强制覆盖、删除参数）整族一次写入，编辑器里同一模型内重复的路径会被拒绝。
- 保存前会自动重新读取一次配置：如果同一分组在你编辑期间被别人改动，页面报告冲突并保留你的草稿，让你先比对再保存。
- 网络中断或 5xx 属于“结果未知”。未知结果只能通过回读原操作确认，系统不会自动重发写入。
- 页面分别显示“已保存”和“是否已生效”。CPA 异步重载配置，生效需要回读确认。

“代理地址”不接受带账号密码的 URL。其余取值范围的校验由 CPA 完成，页面只做类型与产品规则检查。

归属只读区列出由 API 密钥、提供商、账号、日志、系统等其它工作区管理的配置项；这些字段不要在本页重复编辑。

## 加权轮询路由

需要让同一优先级内的多份凭证按比例承接请求时，在可视化配置中把路由策略设为“加权轮询”，对应的源文件配置是：

```yaml
routing:
  strategy: weighted-round-robin
```

CPA 会先筛选当前最高且可用的 `priority` 层级，再在该层级内按凭证 `weight` 执行加权轮询。未设置 `weight` 时默认为 `1`；权重必须是整数，最大为 `1,000,000`；非正数会让该凭证在加权轮询策略下不参与分配。清空 CPAMP 中的权重输入会移除显式 `weight`，恢复默认值 `1`。

此策略和权重字段需要 CPA 本身支持 weighted routing。旧版 CPA 可能忽略或拒绝这些配置；升级到包含该能力的 CPA 构建后，再到 [AI 提供商](./ai-providers.md)或[凭证管理](./accounts.md)设置各凭证权重。验证比例时应使用多个独立请求；启用会话亲和性后，同一会话可能持续绑定既有凭证。

## 保存后怎么验证

1. 回到仪表盘确认连接和采集器状态。
2. 进入 [AI 提供商](./ai-providers.md) 确认提供商配置仍然存在。
3. 发一条低成本请求。
4. 到 [请求监控](./monitoring.md) 看是否出现请求事件。
5. 如果改动涉及用量统计，到 [用量分析](./usage-analytics.md) 检查统计是否更新。

## 常见误区

- CPAMP 管理员密钥、CPA Management Key、客户端 API Key 和提供商 API Key 是四类不同密钥。
- 关闭 CPAMP 请求监控采集器，不等于清空 CPA 用量队列。
- 模型价格只影响 CPAMP 成本估算，不会改变提供商实际计费。
- 环境变量来源的配置要改部署环境并重启，不能只在面板里保存。
